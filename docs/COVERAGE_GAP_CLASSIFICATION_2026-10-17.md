`covered_partial` (AV-MASSASSIGN-01, WSTG-INPV-17) and 36 gaps. Eleven requirements

INPV-18, INPV-07, INPV-19, CRYP-04, INPV-11); the table below lists only the 25 that
remain, regenerated by the script. Here `gap_unimplemented` means that **no
`EvidenceCase` aspect is declared** in `coverage_manifest.REQUIREMENT_TESTS`. It does not
mean the product lacks the check. A gap closes only when a test records fresh run-bound
evidence for a declared aspect; a `covered_partial` requirement is proven only for the
named aspects (see `coverage_manifest._CALLER_EVIDENCE`), not as a whole.

**Method.** Each check's `confirmation` field (from `coverage_model.CHECK_CATALOG`) is
mapped to the validator module of the same name. Tracked `harness/test_*.py` modules that
reference that validator class are then counted. A module counts as caller/fixture
evidence when it drives a production caller or owned fixture (`test_leg_live_verification`,
`test_pipeline_gate`, `test_smoke_*`). This is a name-based heuristic: it shows where
evidence could be wired, not that a given test already proves the aspect.

## Notes

- Requirement status is evidence bookkeeping. An implemented validator does not count as
  covered, and none of this establishes detection efficacy on a real target (I13).
- Each wired pair has a fault-injection check: with the leg's async egress cut, every
  bound test must fail (`LiveLegVerificationTest.test_bound_aspects_fail_when_the_leg_is_disconnected`
  and the authorization-smoke twin). Without it, five legs (SSTI, SSRF, command injection,
  deserialization, stored XSS) would pass their controls hollowly, because a failed send
  is reported as a clean `not_confirmed`.
